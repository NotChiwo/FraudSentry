# FraudSentry text model — training report

Generated by `npm run train:text` (tools/train-text-model.ts). Seed 42; running it again gives exactly the same model and numbers (a test checks this).

## Data
- **Synthetic dataset:** 2400 Philippine SMS / chat messages (1200 scam, 1200 legitimate) generated from 66 templates in English, Tagalog and Taglish with random slots (bank / e-wallet, amount, link, phone, name, courier) and variations (case, "po", punctuation, typos). 2.0% of labels flipped on purpose (real labels are never perfect). Every message: `docs/text-model/dataset.csv`.
- **Split (stratified):** 1680 training, 360 validation (watched during training), 360 test (used once, at the end).
- **Hand-written test set:** 60 messages written separately from the templates and never trained on (`docs/text-model/handwritten-test.csv`).

## Model and training
Logistic regression on a binary bag of words and two-word phrases (2360 features that appear in at least 2 training messages). Links, phone numbers, amounts and codes are replaced by placeholders ([suspicious link], [phone number] …) so the model learns the kind of thing, not the exact value. Trained by mini-batch gradient descent: 30 epochs, batch 32, learning rate 0.5/√epoch, L2 0.0001. Training took 1.5 s including the learning curve and cross-validation.

## How the app uses it
The message checker keeps every rule-based finding and adds the model: final score = max(rules, 0.6 × rules + 0.4 × model probability). The model can raise a message the rules missed; it never lowers one the rules flagged.

## Limits
The training data is synthetic: it proves the method (the model is trained, learns sensible words, and generalises to messages written differently) but some learned weights reflect the templates (e.g. a courier or bank name that appears more often in one kind of template). Real collected and labelled messages are needed for field accuracy; `npm run train:text` retrains on whatever dataset `textDataset.ts` provides.
